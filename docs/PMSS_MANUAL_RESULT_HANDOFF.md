# PowerBid 报价 → 老师 PMSS 结果：人工交接首版

## 已实现的业务链路

此次交付并未申请、使用或假设老师 PMSS 平台的报价写入权限。本阶段使已在 PowerBid 网页跑通的“五段本地报价建议”与真实课程练习的**人工出清结果**在一个工作台实现安全的描述性比较。

1. 进入 PowerBid → **PMSS 市场分析**，导入**经过白名单脱敏的同日24小时只读历史市场快照**。该快照仍会在后端验证发电机组、报价约束、原始案例日期及可用的出清/网架资料。
2. 选择目标机组和报价候选区间，点击 **生成分段报价**。显示单区域24小时简化模型推荐的五段价格/数量组合、模型收益和历史原报价基准对照；点击原有 **下载审核 JSON** 保存审阅结果。 也可点击新增的 **导出24小时人工核对 CSV**，得到24×5=120行时段/段号/起止MW/价格表，便于核查与手动录入；这120行仍由**同一条五段曲线重复24次**形成，并非独立优化的24套报价，也不是可直接提交老师平台的正式文件。
3. **人工**在老师 PMSS 官方页面核对该课程案例、目标机组、申报限制，获授权后按老师要求录入与确认报价，并由授权人员按课程规则运行出清；当前页面**不会自动登录、提交、出清或发送任何 API 请求至老师平台**。
4. 从老师平台只读取得该次案例的出清观察结果，导出脱敏JSON。返回 PowerBid，明确勾选“已在老师平台人工提交且结果对应这份方案”的声明，然后点击 **导入出清结果**。
5. PowerBid 将该结果上传至自身同源后端的 `POST /api/pmss/manual-clearing-review`，校验原始研究案例日期与结果日期、市场类型DA、24时段、目标机组ID和容量、当前五段曲线及用户确认；**重新执行本地五段报价模型**计算对照，显示老师观察到的中标量、老师提供的 `income` 字段合计以及24小时中标量 MAE。

## 重要：它尚不是官方自动出清

目前已验证的五段报价优化器仅支持 **24小时共用同一条五段供给曲线**，不是每小时24套独立曲线。当前传出的文件是**研究审核 JSON**，不是老师 PMSS 的正式提交报文；自动提交/触发出清/结算前仍需有老师平台的授权接口及真实联调。

人工勾选只意味着“操作者声称结果对应当次报价”；文件来源没有老师数字签名或可独立校验的交易ID，所以：
- `association=OPERATOR_ASSERTED_ONLY`；
- `teacher_result_authenticated=false`；
- `candidate_bid_causality_verified=false`；
- `reported_income_is_net_profit=false`；
- `automatic_submission_enabled=false`；
- `pmss_write_performed=false`；
- `pmss_clearing_executed=false`。

历史原快照内的原有 `results` **原样再次提交会被拒绝**，避免把旧出清记录直接冒充新报价验证。改变数据格式绕过旧结果检测不能等同于证明出清因果关系，因此仍必须人工核验。

## 安全结果文件格式

支持两种只读JSON格式。第一种沿用现有脱敏快照，必须具有日期和结果：

```json
{
  "caseDate": "2025-09-01",
  "results": {
    "marketTypeAtom": "DA",
    "periodNum": 24,
    "unitResults": [
      {
        "elementId": "TARGET_UNIT",
        "marketTypeAtom": "DA",
        "power": {"datas": [0, 0]},
        "price": {"datas": [0, 0]},
        "income": {"datas": [0, 0]}
      }
    ]
  }
}
```

**注意：上面数组缩写只是说明字段，不能直接导入。** 实际的 `power`、`price`、`income` 数组均须覆盖24小时。其中 `power` 是必须提供的完整24小时序列，`price` 和 `income` 缺失或部分缺测时仍可比较中标量，但不会虚构收入或结算利润。若结果文件中包含老师系统的其他单位，ID必须属于已导入案例机组列表，目标机组必须唯一。程序不存储原始上传结果。

也可以把 `caseDate`、`marketTypeAtom`、`periodNum`、`unitResults` 放在同一个对象里。禁止上传 Cookie、session、Token、账号密码等认证信息；会被私密字段过滤器拒绝。

## 测试

`tests/test_pmss_manual_clearing.py`使用人工构造的课程合成样本，覆盖成功导入、24小时完整结果、原始出清重复、日期不一致、目标机组不匹配、非DA或23小时数据、过大出力、报价价格越界与分段不连续等。全部检查通过不等于老师平台真实新报价联调通过。

本功能保持原有机组、网架、联合MILP分析不变，不修改 Loom 原版液态玻璃鼠标、登录注册或 Smirel 商标。正式生产是否部署、用户登录状态、授权信息要在合并后单独验收。

## 下一步真正需要的对接

与老师确认：正式出清结果能否携带其唯一案例/报价提交关联ID，是否开放只读“该次报价”记录，是否授权自动触发出清及提供正式提交接口。有上述证据才可能从 **人工声明关联** 升级为平台独立身份核验及一键出清。

在此前，**核心网页演示与本地策略研究可用，自动出清不可用**。
