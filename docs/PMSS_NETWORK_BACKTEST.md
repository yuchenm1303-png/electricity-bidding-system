# PMSS 真实网络诊断与本地报价模型回测

本模块以已经出清的 PMSS 历史结果作 **事后诊断**，不假设历史节点电价、支路潮流或影子价格在修改报价后保持不变。

## 数据输入与 API

真实 2025-09-01 日前场景读取成功：

- 10 台机组，机组中标出力和价格各 24 时段；
- 39 个节点的 LMP，各 24 时段（原始 PMSS JSON 的字段名是 powerFlow）；
- 46 条支路的 powerFlow、beginNodePrice、endNodePrice、shadowPrice、blockSurplus，均为 24 时段；
- 负荷是 PMSS 场景的真实日前节点负荷输入 39 个 Bus 的汇总，非清算后的发电量代替，更不是未来的预测。

详见 PMSS_VERIFIED_RESULTS.md、PMSS_DA_LOAD.md。

## 新增诊断

powerbid.pmss_diagnostics.analyze_historical_network：

- 每小时节点价格最小值、最大值、平均值与价差；
- 有非零影子价格的线路数与影子价格绝对值峰值；
- 线路潮流绝对值峰值、非空数据覆盖率；
- 按非零影子价格时段数及峰值排序的历史线路清单。

无线路额定传输能力参数时，**影子价格不代表线路过载，也不能计算线路利用率**。

powerbid.pmss_diagnostics.compare_baseline_to_pmss：

- 将目标机组**原始提交报价**在本地单区域统一价模型的 24 时段中标出力，与老师 PMSS 实际出力对比；
- 输出逐小时差值、MAE、RMSE、可用时段数；
- PMSS 的机组节点结算价格与单区统一电价不等价，因此不以价格误差简单判定预测精度；
- 不对“推荐新报价”假装存在已经出清的真实市场反馈。

## 真实历史回归发现

服务器授权会话本地私有快照完成验证：

- 39 节点、46 支路，总计 936 个历史节点时段、1104 个历史支路时段都有数据；
- 历史所有 24 个小时至少一条支路具有非零影子价格；
- 在已有单区域引擎上，与 PMSS 实际机组中标出力相比：G30 MAE 约 3.16 MW；G31 MAE 约 349.52 MW；G34 MAE 约 81.29 MW。

这说明基础单区优化模型对某些机组拟合较差。上述误差是**该一份历史样本上的回测指标**，不能据此估计未来精度或代表网络约束已加入模型。

## 安全的快照流程

可信服务器上，脚本 scripts/export_pmss_snapshot.py 可采用 `--pmss-da-snapshot` 开关：调用现有的只读 TeacherPlatformAdapter，从 PMSS 获取场景日前负荷、机组曲线及实际三类结果；通过白名单导出无需 Cookie/Token 的 JSON。本功能不调用 save_unit_bid 或 simulate/execute。

输出在服务端应限定访问权限、存放在 Git 工作目录外；不要通过公开无需认证的 Web 路由暴露历史教学数据。PowerBid Streamlit 页面可通过文件上传读取该快照，展示真实历史结果与本地模拟，不需要在浏览器持有 PMSS 凭证。

## 尚未支持

- 真实线路 reactance/容量、节点与机组映射的验证和物理 DC/AC OPF；
- 机组启停、最小稳定出力、爬坡等多时段约束；
- 目标报价实际提交后的真实 PMSS 出清反馈和迭代。

要可靠地优化实际网络结算利润，必须先补齐约束和物理模型，再在**获得明确授权**的前提下测试受控写入与出清。不得把当前结果标为“网络约束优化已完成”。
