# 报价决策模型

这一页专门回答课程研讨中最容易混淆的问题：**软件里的报价从哪里来，数据从哪里来，哪些是我们自己假设的。**

## 1. 软件不“凭空给价格”

PowerBid Lab 把报价决策拆成三层：

```text
输入数据
  ├─ 本机组：边际成本、可申报容量
  ├─ 市场：负荷、结算时段
  ├─ 竞争者：报价与容量
  └─ 后续：风光出力、线路、电抗、历史价格
        ↓
候选报价 / 报价策略
        ↓
出清引擎
        ↓
中标量 + 出清价
        ↓
收入 - 成本 = 利润
        ↓
比较候选报价并给出推荐
```

当前第一版用可解释的网格搜索，不把“AI”当黑箱：给定一个报价范围，逐个试算并比较结果。

## 2. 数据来源必须标记

场景使用 `data_source` 字段：

| 值 | 含义 |
|---|---|
| `platform` | 老师报价出清仿真平台/API/导出文件 |
| `course` | 课程材料给出的参数 |
| `public` | 可追溯的公开市场数据 |
| `synthetic` | 为教学或压力测试人为构造的数据 |
| `unknown` | 暂未确认来源 |

`data/sample_market.json` 当前属于 `synthetic`，因此只能用于验证算法流程，不能冒充真实市场报价结论。

## 3. 为什么还需要风险分析

只针对“一个固定负荷 + 一套固定竞争报价”求最优值，很容易得到一个只在该情景下有效的答案。

因此第二版增加压力测试：

- 负荷上下波动；
- 竞争机组报价上下波动；
- 同一个目标报价在所有情景中重新出清；
- 同时计算平均利润和下行情景利润。

风险得分采用一个容易解释的组合：

```text
风险得分
= (1 - 风险厌恶系数) × 期望利润
+ 风险厌恶系数 × 下行情景平均利润
```

风险厌恶系数为 0 时只追求平均利润；越接近 1，越重视不利市场情景。

这不是对真实未来的概率预测，而是**敏感性/压力测试**。等后续有真实历史数据后，可以把人为等权情景替换成预测模型给出的概率分布。

## 4. 等老师网页详情后再接什么

网页接口和字段没有确认前，不猜 API，也不写死抓取逻辑。确认后只补 Adapter：

```text
老师平台原始数据
        ↓
TeacherPlatformAdapter
        ↓
PowerBid 统一场景模型
        ↓
现有报价优化 / 风险分析
```

这样老师平台怎么改字段，都不会迫使核心算法重写。

## 5. 后续成熟路线

1. 平台数据适配与字段校验；
2. Bus / Line / reactance / transmission limit；
3. PyPSA 网络约束出清；
4. 24 小时多时段与风光预测；
5. 历史价格和竞争者行为场景；
6. 风险约束、多目标优化；
7. ASSUME 风格 Agent / 强化学习报价实验。

当前原则：**先把可验证、可解释的基础链路做对，再逐层增加复杂度。**
