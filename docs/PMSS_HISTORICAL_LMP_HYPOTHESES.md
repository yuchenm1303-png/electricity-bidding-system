# PMSS 历史节点电价：两小时异常与1001输出上限假设（阶段八）

## 已核实的历史复算发现

在已授权、只读的 2025-09-01 PMSS **39节点、24小时** 案例，PowerBid 用**已保存的原始报价**和经核实的 DC 网架重新运行全部24小时线性出清，比较所有 **936个节点时段**的本地无损 DC LP 等式对偶边际电价和平台历史观察值。

| 比较方式 | 节点历史价格 MAE | 严格匹配点数 |
|---|---:|---:|
| **原始 DC LP 对偶节点价格，不作任何显示变换** | **397.36965812** | **874 / 936** |
| 对原始 DC 模拟节点价**事后假设输出上限1000** | **0.066239316** | **874 / 936** |
| 对原始 DC 模拟节点价**事后假设输出上限1001** | **0.000000** | **936 / 936** |

全部差异只在第11、17小时：每小时31个节点，**本地 DC LP 原始节点价7000，而PMSS历史记录为1001**。其余两个小时内的8个节点、以及另外22个完整小时的全部39节点价格已与本地 DC LP 对偶值一致。

案例快照中的**当前新报价**申报价格上限是1000，但**历史已保存报价**存在7000、8000的段价格。PMSS 历史观察价格1001（不是1000）恰好将本地7000节点价截为1001而其他已匹配值不变。

### 特别重要：这并未证明 PMSS 的实际结算价格规则是 min(DC LMP,1001)

这只是一个**单日历史样本的报告数值拟合假设**，甚至不能排除平台历史数据显示、结算金额单位、整数化、市场安全上限、系统特殊行情或其他定价过程的解释。当前已经证实的是历史原报价数据在上述变换**之后数值吻合**，不是规则被证明。

因此不能：

1. 把已观察到的1001直接硬编码为正式清算或利润模块的价格上限。
2. 截断原始报价7000/8000来“改写”历史数据；它们是历史证据，而非当前新报价的合法范围。
3. 把这一天936/936吻合，误认为新候选报价、其他日期、其他竞争情景也能正确复现 PMSS 结果。
4. 在未确认 PMSS 市场限价、节点电价与结算口径前，以该假设推断新策略在PMSS的利润。

## 新增代码和页面

- **src/powerbid/historical_price_hypotheses.py**：严格要求标为 historicalBacktestOnly 的已核实历史快照、日期、同一份 DC 网架和真实 DA 节点观察；每小时按**原始保存报价**重新求DC LP。将原始模拟边际价分别与原样、用户显式输入的若干候选**事后价格输出上限假设**比较。报告每小时观测覆盖、节点价格MAE/RMSE、匹配节点、改善/变差节点数量。不会修改求解器目标、出力分配、历史报价、原始节点价格、模型策略报价或结算。
- **app/pages/6_模型可靠性回测.py**：在同成本多解诊断下加入“历史节点电价上限假设”表，给出原DC模型、假设1000、假设1001三种结果和逐小时差异，并将**只有汇总统计**的结果包含于现有脱敏审阅JSON。
- **tests/test_historical_price_hypotheses.py**：合成两节点高报价下的1000/1001对照、没有高报价时原价不变、截断让效果变差时如实报告、缺失不补零、历史 ID/日期/候选假设合法性验证。

代码仅为离线原始报价历史研究，**没有 PMSS 网络请求、保存报价、执行出清**；所有原始私有快照留在可信服务器，GitHub只包含代码/脱敏指标文档与合成测试。

## 下一步应优先查证

1. 老师 PMSS 节点价格历史查询 API 中，1001值究竟是实际结算节点电价、显示边界、数据库哨兵值，还是某个出清结果限额/特殊处理值。核对课程说明或平台相关源码的**实际字段意义**。
2. 读取更多真正不同日期的**只读原始报价与原始节点价格**，对1000/1001假设做留出集测试；不能在第11、17小时拟合后回头宣称泛化。
3. 按最新市场规则严格拒绝任何超1000的新候选报价。历史7000/8000属于历史已保存记录，不能自动继承为未来合法。
4. 即使定价显示规则被核实，还需区分系统价格、电能量结算价、节点边际价和可能的补偿机制；不能仅用看起来更准确的拟合价格取代正式利润结算。
