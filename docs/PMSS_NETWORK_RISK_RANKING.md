# PMSS 实际网架下的多情景五段报价排序（V1）

## 为什么这阶段不是继续加 UI

以前流程是：单区域统一电价模型选出一个五段曲线，再用真实 39 节点/DC 模型验证一次。这个流程容易先入为主，最佳单区域策略不一定在拥塞网络中表现最好。

本阶段新增 `powerbid.pmss_network_rank.rank_network_bid_strategies`。先产生**符合当前市场价格规则**的报价候选，再调用已有 `network_strategy.compare_network_policies` 对每个候选**分别重新出清24小时真实网架**，在模型内同时比较预期收益与不利情景收益。

- 候选：发电机组可变成本+{0、20、50、100}的透明四类报价，使用现有 `generate_policy_plan` 构建最多5段价格—电量曲线。不允许偷偷裁剪越界报价，所有候选先经 `validate_new_curve` 检查。
- 历史原报价**只作基准观察**，不作为新候选，尤其历史保存报价含7000/8000而当前价格限制为0—1000时。
- 三种**合成**竞争报价情景：竞争方历史申报价×(0.95、1.00、1.05)。这是敏感性测试，**不是来自真实预测的概率**。
- 固定原始日前节点负荷，对每个报价和压力情景每小时求解现有DC网络线性规划，受节点供需、支路电抗和热稳定容量约束。
- 风险得分=`(1-risk_aversion)*期望利润代理+risk_aversion*下行情景利润代理`；仅在被测试候选内排序，不能宣称全局最优。
- 若历史机组报价与当前市场上限冲突，`modeled_better_than_baseline=null`；不会错误把跨规则基准比较当成真实改进。
- `historical_evidence_days=0` / `validated_for_real_bidding=false` / `safe_for_live_submission=false`：用户仍需另收集3日及以上独立历史数据、核实PMSS价格机制后再做可信度判定。

与已有 `joint_market.py` 的差别：**本次研究仅做独立24小时DC出清**；不包括机组启停、初始状态、爬坡、最短开停机和实际PMSS结算规则。虽然项目另有24小时联合MILP研究引擎，本阶段没有把它自动应用于生产建议，不伪造机组技术初值。

## 接口与页面

`POST /api/pmss/network-rank`

请求仅包含脱敏历史市场快照（`historicalBacktestOnly:true` 且有 `dcNetwork`）、目标机组、风险厌恶程度（0—1）、价格压力（0—15%）。所有运算在本站 FastAPI 内存中完成。调用共用并发信号量，模型大小受服务器限制；不需要PMSS Cookie或在网页端访问学校网站。

网页 `PMSS 市场分析` 的新独立面板可以直接运行网络优先排序，不需要先跑单区域优化。展示候选风险得分、下行情景模拟利润、中标电量、五段曲线；**不生成可直接提交PMSS的正式报文**。

## 质量门槛与后续

这不是独立的PMSS策略优劣验证：历史记录只有原始报价的真实出清，候选报价未在PMSS做过反事实出清。当前日期只有 2025-09-01，PMSS 多日历史不足。任何模型得分都必须继续标为研究参考。

下一步推进价值更高的联合机组约束：在取得全部机组可信的初始状态/启动与爬坡参数前，不允许用猜测参数来声称24小时真实联合MILP验证完成。
