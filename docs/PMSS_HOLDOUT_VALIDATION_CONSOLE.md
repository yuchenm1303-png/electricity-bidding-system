# 第二十一阶段：PowerBid 历史跨日留出报告审核控制台

## 为什么需要这个界面

2025-09-01/02训练与09-03留出真实历史原始报价回测已经揭示：机组ID正序在训练日MAE为18.4165MW，优于规范化普通LP的26.7264MW；但在第三日，正序变为22.8039MW，**劣于普通LP的21.5158MW**。这说明不能把训练期拟合较好的同价分配规则当作老师真实出清规则，也不能声称它能预测未来新报价利润。

第十八至二十阶段已增加训练/留出区分、每日MAE、样本报价重复识别以及训练阶段冻结的保守参照。但实验结果此前主要保存在服务器私有JSON中，没有专门的网页版安全报告展示和数据一致性复查。实际敏感历史原始行仍留在授权服务器，不应为了展示而上传至普通工作台。

## 新增后端只读验证

`src/powerbid/pmss_holdout_gate.py`：新增 `review_holdout_report`，仅接受上一阶段`scripts/report_pmss_tiebreak_holdout.py`产生的**完整、匿名、版本匹配**的历史报告。它逐项重新计算：

- 按日期排列的训练、留出分割，至少2日训练和1日留出；
- 三条事先声明的DC模型同成本分配约定的每日日均MAE与训练/留出聚合MAE；
- 训练日唯一选优规则和固定并列处理；
- 提前声明的1MW（可配置）训练门槛是否真的逐日满足、原报价多样性和保守参照回退理由；
- 训练赢家与保守参照在留出日的MAE及相对普通LP的改善/恶化、最差单日恶化；
- 留出日是否复用训练报价、实际覆盖和非实盘使用声明；
- JSON含未知根字段、报告“已认证/可实盘/已验证利润”伪声明、非法数值NaN、日期错位或每日汇总不一致直接拒绝。

返回的每个状态始终标记`liveBidAllowed=false`、`pmssCounterfactualValidated=false`、`profitForecastValidated=false`、`sourceAuthenticatedByThisReport=false`。

这里的“审核通过”只表示**上传的匿名报告内部算术和安全声明自洽**，不提供平台原始数据签名、没有再读取老师老师PMSS实测，也不说明真实新报价反事实出清已验证。

## 研究状态分类

- `TRAINING_GUARD_BLOCKED`：训练期门槛、报价多样性或训练逐日改善不满足，使用普通LP作为保守参照；这只是后续研究的基准，**不是证明其有预测优势**。
- `HOLDOUT_DETERIORATION_OBSERVED`：虽然训练筛选通过，但锁定的保守参照在某个留出日比规范化普通LP误差更大，明确提示不能外推。
- `DESCRIPTIVE_ONLY_INSUFFICIENT_EXTERNAL_VALIDATION`：没有发现上述阻断证据，**仍因为样本规模与真实市场验证不足，仅保留描述性研究状态**；绝不能据此升级正式报价使用权限。

研究状态由已经固定的训练决策和独立留出误差生成，不重新选择训练赢家。所有判断都不得改变线上报价策略、原有设备约束或市场结算方式。

## Web React 使用

现有`frontend/src/PMSSWorkspace.tsx`新增独立的“历史分配规则 · 跨日期可靠性审核”面板，无需上传PMSS原始快照，也不依赖是否加载当前单日原报价研究。只上传**经过匿名脱敏、最大120KB的回测汇总JSON**。请求`POST /api/pmss/holdout-gate`仅在内存审核并返回数值汇总，不保存文档、不调用PMSS网络接口、不执行报价或出清。

网页呈现训练期选择的规则、训练审核后的保守参照、二者在留出日期的MAE和相对普通LP的差异、报价复用比例、单日最大恶化，以及训练失败的明确原因。页面不展示原始机组ID、原报价段、历史出力明细或凭据；发现报告中的矛盾时给出通用422提示以避免回显污染文本。

## 使用边界

真实历史原始文件受可信服务器文件权限保护。本阶段没有利用新接口读取受保护的私有原始快照，也没有宣称已生成更新后的真实三日逐日审核结果。需要合法访问权限的操作者先离线运行原有`scripts/report_pmss_tiebreak_holdout.py`，只把生成的**匿名聚合报告**导入工作台。

新审核器保证内部数值关系自洽，不保证源平台真实性，也不是自动模型上线批准器；这个差别必须向学生小组及老师展示。
