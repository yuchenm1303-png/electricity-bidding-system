# PowerBid · PMSS 多日期历史回测与模型可信度闸门（V5）

## 结论与定位

2026-10-08 的主分支已经由另一个开发窗口合入了“真实 PMSS 39 节点 → PowerBid DC 网架”的只读桥接，见 [PMSS_VERIFIED_GRID_BRIDGE.md](PMSS_VERIFIED_GRID_BRIDGE.md)。**连接数据 ≠ 模型正确**：已记录的 2025-09-01 案例中，基础 DC 模型线路潮流绝对值 MAE 约 43.34 MW，节点电价 MAE 约 397.37（真实价格单位/市场结算口径尚需确认）。

此阶段不再复制连接器，不改老师平台，不把某一天的回测误差当成可用于未来报价的质量保证。新增独立 **PMSS 原报价历史 replay → 多日期误差 → 时间顺序留出检查**。

核心函数：\`powerbid.historical_validation.validate_historical_day\` 和 \`judge_historical_model\`。

## 1. 输入要求与安全

逐日期输入由可信服务器通过**已有只读白名单导出器**生成的脱敏 JSON，须同时有：

- \`historicalBacktestOnly=true\`，\`caseDate=YYYY-MM-DD\`；
- \`unitTree\`、\`unitBids\`、\`marketSystem\`、\`demandForecastMw\`、\`forecastSource\`；
- 已验证电网 \`dcNetwork\`，包含完整机组—节点映射、线路电抗和限额、逐节点 24 小时日前负荷（与快照汇总负荷一致）；
- \`results\`：原始案例的真实 PMSS **DA** 机组中标、节点电价、支路潮流。

历史日期必须不同。所有机组 ID、节点 ID、线路 ID 要与已核实电网一致。没有节点数据、线路数据或原始报价数据不会猜测补齐。无网络访问；不会向 PMSS 发送任何请求，也不会保存/执行出清。

**私有快照不得提交到 GitHub，也不应部署到无需认证的公开静态目录。** 只有报告指标可导出；CLI 生成的可选报告文件为新建文件、0600 权限、拒绝覆盖。

## 2. 每日误差计算

每天只读取 PMSS **已经提交的原始 24 小时报价**，基于受信网架重新运行 DC LP 24 次，不给推荐候选报价套用旧真实 LMP：

- 全机组中标 MW：MAE、RMSE、有效时段数 / 期望时段数；
- **每台机组** 中标 MW：MAE、RMSE、数据覆盖率；
- **每个节点** LMP：MAE、RMSE、数据覆盖率（按误差从大到小排序定位价格异常）；
- **每条线路** 潮流幅值：MAE、RMSE、数据覆盖率（按误差从大到小排序定位可疑支路参数）；
- 全节点模型 LMP 与真实 PMSS 节点价格：MAE、RMSE、覆盖率；
- 全线路**潮流绝对值**误差：MAE、RMSE、覆盖率，暂不强行假设 PMSS 流向相同；
- 全日误差最大的时段（机组出力、节点价格分别计算每小时所有可用点的 MAE）。

记录中的 null 是缺失值，**不是0**。错误模型也不能用“平均误差小”掩盖单机组、单小时的大偏差。

所有报价/价格均必须对应同一个日期，模型不预测未来。程序不将 PMSS 的历史结果当作新候选报价的反事实“中标情况”。

## 3. 模型可信度闸门

门槛是**用户提供的科研要求，不是软件臆造的国家规范**：

- 至少 3 个不同日期，默认将**时间上最新的日期**用作独立留出验证；
- 明确设置可接受的“全机组中标量 MAE（MW）”、“节点电价 MAE（原价格单位）”；
- 历史机组中标、节点电价、线路潮流数据覆盖率均达到自定最低要求，默认 95%；
- 所有日期核实过的电网拓扑、线路电抗/有功限额和机组—节点映射必须完全一致，以 SHA-256 **参数指纹**比较；不同网络不能拼成同一模型的回测；
- 日期重复直接拒绝。

输出：

- \`NOT_VALIDATED\`：证据不足、失配或误差过大；必须展示原因；
- \`HISTORICAL_BASELINE_WITHIN_TOLERANCE\`：仅表示**原始报价历史基线**在保留日期和自定阈值范围内的模型拟合情况，并不代表**新报价的 PMSS 结果被确认**。

另有永远为 \`false\` 的 \`validated_new_bids\` 属性，避免前端错误展示“新策略已验证”。

特别提醒：只有模型回测、没有真实独立试报和市场结算复核，不能把任何新方案的“模拟利润增加”称为实际增益。即使留出集检测成功也不能据此宣称模型能够准确预测市场操纵或策略互动。

## 4. 两种实际使用方式

### 页面

安装 \`pip install -e '.[ui,strategy]'\` 后：

\`\`\`sh
streamlit run app/streamlit_app.py
\`\`\`

选择「模型可靠性回测」页面，同时上传 1–10 个不同日期的脱敏快照。手工设置机组出力/节点电价最大允许误差、最小覆盖率、最少日期和留出天数。单日期允许诊断，但是**绝不输出通过验证**。

页面展示按日期、按机组、逐节点、逐线路的 MAE/RMSE、缺失率和误差热点，最终导出**只含模型指标**的 JSON。

### 可信服务器 CLI

\`\`\`sh
python scripts/validate_pmss_history.py \
  --max-unit-mae-mw 20 \
  --max-nodal-price-mae 50 \
  --min-coverage 0.95 \
  --min-days 3 \
  --holdout-days 1 \
  --output /tmp/powerbid-history-validation-report.json \
  /private/day01-sanitized.json \
  /private/day02-sanitized.json \
  /private/day03-sanitized.json
\`\`\`

**示例中的误差上限只是用户输入示例，不代表对 PMSS 适用的合格标准。**

CLI 的退出码：0 代表历史基线满足自定门槛，2 代表不满足（报告依然可以生成），1 代表数据拒绝或 I/O 错误。默认不写文件，只向终端打印不含原始报价、Cookie、Token、原始支路结构的指标报告。

运行测试：

\`\`\`sh
pytest tests/test_historical_validation.py tests/test_validation_cli.py -q
ruff check .
\`\`\`

## 5. 明确的下一阶段

1. 使用**不同历史日期**（尽量不同工况、负荷峰谷、网络拥塞程度）的受授权脱敏数据完成留出检验；当前仅核验的一天不能推定未来准确度。
2. 对比机组功率、节点价和线路潮流，找出误差集中于哪些时段/机组/节点，再核实 PMSS 成本、线路/变压器、电网损耗、备用、限额与实际定价规则。不要直接为了匹配结果任意修改物理参数。
3. 在专门授权的教学测试案例、严格的试验次数预算及回滚机制下，进行真实 PMSS 报价重出清，才可评价候选策略的真实收益。
4. 如需正式将可靠性闸门接入 React 主工作台，可以复用本阶段的纯 Python 函数，避免与另一窗口正维护的前端/接口文件冲突。
