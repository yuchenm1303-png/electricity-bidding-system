# PMSS 39节点网络约束试算（本地 DC-OPF V1）

## 目标与严格边界

PowerBid 继续保持原有架构。老师 PMSS 是真实课程出清环境；PowerBid 只是内部报价与风险分析工具。

本阶段新增 **39节点/46线路 DC 网络约束线性出清引擎**，从已经在可信服务器上只读取得的网架输入建立：

- 39 母线与24小时每个母线的日前有功负荷；
- 46 条线路的两端母线、电抗 `x`、额定有功传输上限 `ratedMw`；
- 10 台机组的实际接入母线；
- 10 台机组原始分段报价与用户修改后的候选分段报价。

**这是本地近似模型，不是老师 PMSS 真实重出清，也不是完整 AC 电网/SCUC/SCED。**

没有线路额定限制时会拒绝计算，绝不以系统容量或预设值代替。

## DC-OPF 基本模型

在每个时段，优化各发电机组各报价段的中标 MW，以报价成本之和最小为目标。求解以下连续线性约束：

```
所有母线: 发电出力 + 流入线路功率 - 流出线路功率 = 节点负荷
每条线路: f(i,j) = (theta_i - theta_j) / x_ij
每条线路: -ratedMw <= f(i,j) <= ratedMw
每个报价段: 0 <= awardedMw <= segmentQuantityMw
参考母线: theta_reference = 0
```

所有线路变压器变比从真实输入确认为 1。采用统一比例的电抗计算相对有功潮流，不声称 `theta` 是未经基础容量核实的物理弧度。节点平衡约束的 HiGHS 对偶变量仅作为 **PowerBid DC 模型节点边际价格**，不能标为 PMSS LMP。

没有偷偷允许负荷切除：当某小时报价/线路配置不足以满足节点有功平衡时，返回不可行错误而不是给出“最佳利润”。

每小时独立求解，**尚未联合约束 24 小时爬坡、启停、最短开停机及备用**。已存在的 `unit_commitment.py` 是另一套独立机组计划研究模型，不能假装这些约束已经进入当前网络 OPF。

## 真实数据映射与不泄露凭证

可信服务器私有原始网络读取文件：

`/srv/powerbid-platform/pmss-grid-snapshot.json`

旧的24小时市场、报价、结果文件：

`/tmp/powerbid_pmss_readonly_2025-09-01.json`

在服务器有权限的账户里：

```sh
python scripts/merge_pmss_grid.py \
  --snapshot /tmp/powerbid_pmss_readonly_2025-09-01.json \
  --grid /srv/powerbid-platform/pmss-grid-snapshot.json \
  --output /tmp/powerbid_pmss_grid_2025-09-01.json
```

若真实源文件属于 root，须在受控的服务器终端使用适当的权限执行。新的目标文件默认为0600，不覆盖源文件。不会提交到 GitHub，也不会输出 PMSS Cookie、账户口令、Token。

导出器仅以允许字段生成 `grid`：

- `schema = powerbid.pmss.dc-grid.v1`
- `buses: [{bus, loadMw: [24]}]`
- `lines: [{lineId, fromBus, toBus, x, limitMw}]`
- `unitBuses: {<PMSS内部机组ID>: <Bus名称>}`
- `provenance`

所有母线、线路、机组 ID 必须精确匹配，24小时节点负荷汇总必须与原场景日前总负荷一致。多余或缺失字段导致校验失败。真实课程数据只保留在服务器的私有 JSON，不放入公开 GitHub。

## 服务器的历史案例验证

2025-09-01 日前场景：

- 39节点、46线路、10台机组映射一致，网络连通；
- 线路电抗均为正，范围约0.0026–0.0625；额定 MW 范围405–1115；
- 24小时线性网络优化均有可行解；
- 从真实报价基线产生的模拟24小时线路有功潮流，与老师 PMSS 的线路**绝对值潮流**，平均绝对偏差约43.34 MW（46线路×24时段）；
- 模拟节点边际价对 PMSS 历史节点电价的 MAE 约397.37（沿用两侧原始价格尺度，尚需核实 PMSS 电价字段的严格计费口径）；
- G30、G34 等少数机组基准中标量可接近平台，但不同机组差异仍较大；不能以匹配少数机组证明市场规则已完整复现。

**重要**：目前网络约束显著改善部分机组基准出力吻合程度，但节点价格差异依然较大。模型只能用于识别物理输电瓶颈风险和候选报价的本地近似影响；不能直接为真实市场出价下结论。

## 页面操作

React Studio 中的 PMSS 市场分析页：

1. 导入可信服务器生成的脱敏 JSON（可选包含 `grid`）；不能用原始 PMSS 网络请求直接上传。
2. 先运行原有单区域五段报价搜索。
3. 点击“运行真实拓扑网络对照”，对原始历史提交曲线与候选曲线分别使用39节点 DC-OPF复算24时段；查看中标 MW、模型价格、约束活跃的时段与不可行告警。
4. 和 PMSS 原始历史中标作对照，但明确历史结果属于原提交报价，不能当新曲线的反事实收益。

本地 API `POST /api/pmss/network-evaluate` 采用短生命周期内存计算、大小与网络节点上限、单进程限流；没有访问老师平台的地址、帐号，也没有任何保存报价、运行出清的操作。
