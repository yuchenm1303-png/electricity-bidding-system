# PowerBid 第十阶段：候选新报价的同成本出力不确定性筛查

## 解决的问题

此前已发现老师PMSS 2025-09-01的一天历史场景，39节点24小时中有22小时存在多个相同最低报价成本的机组分配。若仅展示某次普通DC-LP求解器输出的“预计中标量”，可能让人误以为这个MW值由报价和电网约束唯一确定。

本阶段把**同成本多解的不确定性**从历史诊断扩展到**新候选报价的离线研究**。不再先拿PMSS真实中标结果“选最接近的排序规则”，而是在没有未来历史结果的情况下，用完全一样的原始其他机组报价、节点负荷及DC电网约束，分别求某个目标机组新报价在每小时的最小/最大可中标出力。

## 数学定义

对每个时段，先在节点和线路约束下求申报成本最低值 C*。再固定供需平衡、线路限额及报价段上下界，限制 C ≤ C*+ε，分别求目标机组 MW 的最大值与最小值。

- 24小时均使用**同一条当前价格规则合法的新申报曲线**；
- 同行机组全部使用快照中的**历史已保存报价**，它们即使高于当前新报价上限也不被悄悄修改；
- 若历史同行已保存报价超出当前规则，会在输出中显式警告，因此不能把该市场环境直接视为今天可用的竞争报价；
- 每个小时独立计算最小/最大中标MW、普通LP返回的一个中标MW，以及区间宽度；
- 报告累计的日最小/最大中标MWh，但**这些是逐小时独立DC最优分配假设下的范围**，并不代表含爬坡、启停、备用、N-1等运行约束的24小时联合可行域；
- 不伪造 LMP 区间或实际利润区间：出力非唯一不证明价格必须唯一，且此前的1001节点价格仅为历史输出拟合假设，不应套用到新报价收益。

## 用户界面和 API

新 Streamlit 页面：

    app/pages/7_候选报价出力不确定性.py

接收经脱敏的同一天PMSS历史研究快照（包含dcNetwork）。选择目标机组与**合法新申报价**，即可查看24小时可中标出力上下界、普通单解轨迹以及不唯一时段统计；可下载只含模拟指标的JSON。当前页面提供单段覆盖机组最大出力的简易研究控件，核心函数支持1—5段新申报。

新的同源只读 API：

    POST /api/pmss/network-dispatch-range

请求复用 network-evaluate 的 NetworkInput 契约：snapshot、target_unit_id、recommended_segments（必填）。服务器有限制的输入大小、节点和线路规模、严格凭据字段过滤、并发互斥；模型线程运行结束才返回指标。缺少电网、遗漏新报价、不满足当前市场限价、节点总负荷不一致等情况全部拒绝。

返回包括：

- 每小时最小/普通LP/最大中标量；
- 最小、最大与普通LP累计MWh；
- 高于默认1MW阈值的不唯一时段个数；
- 历史同行机组价格超当前规则的数量；
- 明确的 confidence_status=RESEARCH_ONLY…、safe_for_live_submission=false、counterfactual_pmss_verified=false、uses_historical_outcomes_as_forecast=false；
- pmss_write_performed=false、pmss_clearing_executed=false。

**这个功能没有调用PMSS平台API、提交报价或执行老师平台出清。** 仅以本地已验证网架和上传的脱敏历史输入计算新候选的离线风险。用户可以使用结果判断单点MW预测是否不稳，但不能将它理解为PMSS真实出力区间或真实利润保证。

## 仍需外部确认的价格规则

在用户此前抓取的PMSS前端JS打包资源中，字符串1001可见于通用代码模块编号及“全部指令”的枚举值，并不能证明1001为PMSS结算电价的上限。2025-09-01历史第11、17小时的价格恰好可用1001上限的**事后变换**解释，依然需要平台后端的真实结算规则、课程资料及独立多日期样本确认。**正式出清和结算算法未作任何价格截断修改。**
