# 阶段十一：正式 React 工作台接入候选报价中标量不确定性（研究模式）

## 实际交付

此前已经合并的后端 \`POST /api/pmss/network-dispatch-range\` 能针对**新合法报价**、原始历史同行报价、已经验证的 DC 网络和逐节点负荷，求解目标机组24小时逐小时的**最小/普通 LP / 最大中标MW**。

之前只有 Python/Streamlit 研究页，本阶段将其接入 React PMSS 主工作台：

- \`frontend/src/PMSSCandidateDispatchPanel.tsx\`：直接复用当前上传的脱敏快照、目标机组和合法报价；明确选择“网络优先风险排序最高候选”或“五段本地搜索候选”，请求只读接口；展示24小时中标区间曲线、逐时段差异表、累计研究MW范围和存在明显同成本分配歧义的小时。
- \`frontend/src/api.ts\`：同源只读API函数 \`analyzePMSSCandidateDispatch\`，复用现有异常反馈。
- \`frontend/src/types.ts\`：新增真实接口输出类型，不使用一个未经核实的节点价格或利润区间填充值。
- \`frontend/src/PMSSWorkspace.tsx\`：PMSS研究页新增入口，更换快照或目标机组时清理旧结果并正确绑定候选来源，不跨机组复用任何旧的价格段。
- 仅导出汇总审核 JSON，不包含历史 PMSS 报价、老师平台账号、Cookie、Token 或历史中标量明细。

**这不是机组启停与爬坡联合模型正式接入，也不是已知真实 PMSS 新报价中标量。**

## 为什么现在把不确定性放到正式页面

2025-09-01 历史 39节点案例显示，22/24小时存在大量等成本最优解，单个 DC-LP 解的机组中标量 MAE 对报价输入顺序和显式分配优先级高度敏感。如果正式 React 界面仍只展示某一组确定的中标量，用户可能错误地将其视为 PMSS 真正会给出的中标结果。

当前界面因此展示：
- **最小中标MW**：在同一最低申报报价成本容差下，该机组独立可获得的最低出力；
- **普通LP解MW**：原始DC-LP求解器选出的一组数学最优解；
- **最大中标MW**：在同一最低申报成本面下，目标机组可获得的最大出力；
- **歧义小时数**：默认判据是区间宽度大于1MW，与确定的市场信用区间没有关系。

累计最小/最大 MWh 只是**24次独立小时DC LP投影的和**，不是允许随意改变机组运行状态、满足24小时爬坡和启停约束的联合可行日发电区间。

## 与机组物理参数证据审核的边界

另一个开发分支已加入独立的机组技术参数真实性审核。缺少启动状态、爬坡、最短启停、启停费用等可靠参数时，前端必须明确提示联合24小时物理可信度尚未确定；不能拿无依据的参数开展真实PMSS出清承诺。

本阶段**没有擅自绕过该审核**。即便有个别案例物理参数齐全，本次候选出力上下界仍是逐小时DC模型输出，并没有联合MILP约束。只有随后明确验证通过的24小时联合优化模型才能报告不同口径的物理可行出力/收益范围。

当前新报价必须遵守快照中的新报价价格上下限、最多5段和机组容量。历史同行报价超过当前价格上限时会明确警告。也不把2025-09-01单日观察到的“1001输出上限”假设硬编码为正式节点电价或利润结算规则。

## 安全与可审核性

- 新前端只调用 **PowerBid 本身已有的只读、有限流量API**；没有调用 PMSS 登录、保存、申报或出清接口；
- 该API强制鉴别和拒绝快照凭据字段、非法价格、缺失网架、超出算力资源预算或缺少新候选的情况；
- 接口明示 \`safe_for_live_submission=false\`、\`counterfactual_pmss_verified=false\`、\`uses_historical_outcomes_as_forecast=false\`；React在服务端报告真实出清成功或上传成功等异常状态时直接拒绝显示。
- 本模块不会将旧私有真实历史案例复制到公共 GitHub 仓库，所有源码测试使用合成数据。

## 验收与后续

后端运行 \`pytest -q && ruff check .\`；前端 GitHub Studio Preview CI 用 Node22 执行 \`npm install --no-audit --no-fund && npm run build\`。由于可信服务器上的系统Node仅有可执行文件、没有 npm，**前端真实构建以GitHub CI结果为准**，不能把本地 Python 编译视为已验证 React TypeScript 构建。

下一步应验证不同日期和真实老师平台规则，进一步把已独立验证完整技术参数的机组模型接入联合DC-UC可行性诊断。只有获得实际授权的 PMSS 新报价试算后，才能将“局部模型研究建议”升级成被老师平台验证的策略。
