# 第九阶段：确定性并列最优分配与 PMSS 历史敏感性诊断

## 目标

标准 DC 线性规划最小化全部机组的申报报价成本，但当多台机组申报价格相同时，最优出力分配可能不唯一。普通求解器只返回一组最优解，甚至仅改变输入报价段排列，也可能返回另一组等成本的出力。

这次新增两种**事先指定的、与历史实际出力无关**的次级规则：

1. 机组 ID 正序优先分配；
2. 机组 ID 倒序优先分配。

**这不是已经证实的老师 PMSS 规则。** 不应只因为某套排序在一天的历史数据 MAE 更低就把它用于未来报价。

## 算法：先保住经济最优，再进行可复现的次级分配

源码：src/powerbid/deterministic_dc_tiebreak.py。

先规范化原始报价段排列，运行既有 DC LP 获得最小申报成本 C*。增加透明的允许成本差额 ε，对候选要求 C ≤ C* + ε。随后按用户指定的机组 ID 顺序，依次最大化该机组中标 MW，每次把已确定的 MW 固定到后续 LP 内。

各阶段始终保留原始报价段 MW 上下界、节点发电与负荷平衡、DC 线路潮流关系和热限额。任何阶段没有证明最优时直接报错。导出的节点价格明确是**原始主目标 DC LP 的诊断对偶价格**，不拿次级 LP 的对偶值冒充真实 PMSS 结算电价。

合成例子：单一节点负荷80MW，G1、G2均可以提供100MW且申报价格都是50。正序优先给 G1=80MW，G2=0MW；倒序优先给 G1=0MW，G2=80MW；两种方案同样达到申报成本4000。

## 真实历史案例：2025-09-01（仅事后分析）

39个节点、46条线路、10台机组、24小时，原始 PMSS 报价与同一天历史出清观察值：

| 同一申报成本的出力选择方式 | 历史机组中标 MAE |
|---|---:|
| 原始文件报价段顺序的普通DC-LP | **47.10233 MW** |
| 规范化报价段顺序的普通DC-LP | **37.04625 MW** |
| 规范排序 + 机组 ID 正序优先 | **19.43825 MW** |
| 规范排序 + 机组 ID 倒序优先 | **63.84642 MW** |

24个小时中有**22小时**的正序和倒序出力结果不同；单小时两种方案所有机组的绝对出力位移之和最多约**1680MW**。这并不是额外用电负荷，而是各机组间抵消的分配变化。二级方案相对原始最小报价成本的最大数值差异约**0.00002563成本单位**，处于公开报告的求解容差量级。

**工程结论：** 单独用一个 LP 解的机组中标 MAE 判定市场模型正确性容易误导。改变等成本解的选择方式会显著改变 MAE，不能据此证明哪种规则就是老师实际采用的规则。此前独立检验发现本案例 PMSS 真实整组中标24/24小时都可处于本地最优成本面；这一新实验进一步揭示单点出力预测对模型退化性的敏感程度。

注意以上是**单日历史比较**，不是未来候选报价的预测能力证明，也不代表次级规则改变了实际 PMSS 结算或利润。

## 节点电价问题仍保持独立

上一阶段发现真实节点价格历史记录在第11和17小时存在集中差异，对模拟价格做1001事后输出上限拟合了当日全部936个节点时段。这仍不是PMSS定价规则已经证实。本次不更改原始报价、不修改正式节点电价、不触及结算模块、不将历史保存的7000/8000报价解释成当前允许的新报价。

## 新增研究页面与测试

- src/powerbid/historical_tiebreak_audit.py：同日四套分配规则的成本与中标量对照，不读取历史观察值作为出力优化约束。
- app/pages/6_模型可靠性回测.py：新增四套分配结果、逐小时中标误差与 MW 重新分配量表，并加入离线审阅指标。
- tests/test_deterministic_dc_tiebreak.py：验证等成本多解、输入排序稳定性、贵报价不能越过廉价报价、电网拥塞限制、数据检验及历史观察值缺失处理。

运行方法：

    pip install -e '.[ui,strategy]'
    streamlit run app/streamlit_app.py
    pytest tests/test_deterministic_dc_tiebreak.py -q
    ruff check .
