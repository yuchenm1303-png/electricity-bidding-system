# PMSS 价格规则一致性与新报价保护

## 已确认的单日数据事实

服务器可信私有快照 `2025-09-01` 的 `marketSystem.spotList` 日前规则显示价格下限0、上限1000、最多5段、24时段共用一条曲线。但是其中一台机组的**历史保存报价**为两个分段价格7000、8000。

同一案例的PMSS节点电价，在第11和17时段31个节点返回1001；PowerBid DC模型原样按历史报价计算时返回7000。其余22小时的39节点电价与PMSS历史数据一致。

**结论边界**：现存数据不能证明过去提交违反当时的规则，也不能证明PMSS对未来所有订单的LMP进行1001裁剪或以1001作为结算价格上限。不得把这种现象当作已确认的结算公式。老师平台当前HTTP访问超时，因此没有完成只读的9月2/3日期补充提取。

## 已做的保护

- `pmss_bid_rule_safety.audit_saved_bid_price_limits` 对只读快照中保存的各段历史报价与**该快照当前规则**比较：返回涉及机组数、报价段数、最高历史报价。**不修改任何历史报价**。
- `validate_new_bid_prices` 检查新候选价格符合PMSS快照规则，并保留网站0—10000安全边界。凡超过当时读取的市场价格上下限的候选，一律拒绝，不能因为历史保存的7000/8000就豁免。
- `POST /api/pmss/optimize` 和 `POST /api/pmss/network-evaluate` 都在计算之前验证候选规则；网页导入快照后显示市场上下限、历史规则不一致告警、自动选择边界作为搜索输入。
- `TeacherPlatformAdapter._request` 仅对GET和显式白名单内的只读POST进行自动重试。对于保存报价和执行真实市场出清的POST（只有显式`commit=True`才可能触发），遇到网络请求失败即停止，**不会盲目重发**，避免上游实际成功但回包丢失造成重复提交。
- 现在仍是本地教学模型：任何模拟收益、DC电价都不代表老师平台已重出清；真实PMSS写入依旧需要单独明确授权。

## 下一步

恢复老师 PMSS 只读访问后，先从网页/公开规则验证极端报价及1001的含义，记录原始接口证据，**不要直接把模型价格7000改成1001**。再读取另两天的脱敏真实历史网架与出清数据，用主分支已有 `validate_pmss_history.py` 做跨日期留出验证；单日证据的结论必须保持`NOT_VALIDATED`。
