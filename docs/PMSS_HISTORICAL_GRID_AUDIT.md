## 新增的电气一致性检查

`powerbid.network_historical_audit.audit_pmss_historical_grid` 严格读取原始 PMSS 网络结果：

1. 每小时观测全系统发电减去日前节点负荷
2. 按线路有向起止节点逐母线检查 **有功平衡残差**：
   `机组已出清MW − 日前负荷MW − (本母线流出 − 本母线流入) MW`
3. 额外按反方向计算一套残差，帮助识别平台支路潮流符号/方向是否与网架定义一致；不为获得更小误差而擅自翻转原始数据
4. 观察到的支路潮流幅值超过其网架 `ratedMw` 的记录次数（此字段约束口径待核验；不直接宣称过载）
5. 校准原始**同一天、同一报价、同一机组 ID 的本地 DC 模拟**：
   - 目标机组中标量 MAE
   - 全网节点价格 MAE
   - 支路**绝对潮流** MAE
   - 24小时逐时段曲线与最大误差节点/线路排名
6. 任一小时观测缺失时，不用零代替，不把该小时计入完整的 KCL 平衡统计，并报告覆盖时段数量

所有数字来自历史结果，不把它们外推为候选新报价的 PMSS 真实收入。当前 DC 单时段模型尚未把热机组启停、爬坡等作为联合约束。仓库已有的联合日调度模块独立存在，当前网络分析网页**不冒充**已启用该联合模块。

## 已实测的现象

对真实2025-09-01 PMSS案例，多个时段上全系统实测发电与日前总负荷相等；以网架给定方向读取历史支路潮流时，节点 KCL 残差在抽样时段平均约8–9MW；整体反转支路符号会产生远大得多的残差。原因尚待验证，可能与课程出清口径、非直流模型、观测数据映射和网络设备建模有关，不能仅凭这份数据确定根因。

此前 DC 模型与历史 PMSS 在同日的线幅值 MAE 为约43.34MW，节点电价 MAE 为约397.37。**节点价差过大，不能直接将模型收益作为可执行报价决策依据。**

## 安全性与 UI

用户上传的是服务器白名单生成的脱敏快照；网页 `POST /api/pmss/network-evaluate` 在返回原报价与候选 DC 结果时，同时附加 `historical_grid_audit`、缺失原因和24小时残差明细。

数据量、模型调用仍受原有接口限制。页面区分“观察到的 PMSS 历史”“单区域模拟”“DC网络模拟”“单日一致性审计”，没有 PMSS 写入和出清调用。

## 节点电价异常：已逐点核实

用原始报价、真实39节点网架和24小时负荷重算，同一日 39×24=936 个节点-时段电价对照得到：

- **22/24 个小时内，全部39节点的模拟电价与PMSS历史电价逐点一致（在数值精度内）。**
- 只有**第11与第17时段**出现误差；两个时段每个均是**31个节点**出现 `DC模型=7000` 与 `PMSS历史=1001` 的差异。
- 两个时段的其余8个节点电价与PMSS完全一致；总计62/936个节点-时段不一致。
- 全日节点电价MAE为397.37，原因主要集中于上述62个结果，而**不是全部时段普遍偏差**。
- 在计算中未擅自将7000硬截为1001，也未把同日观察到的1001当作未来模型的合法统一价格上限。

**待确认**：PMSS 在特殊高价申报、稀缺情景中的LMP后处理、价格上限、结算价格裁剪或哨兵值规则。数据现象与价格钳制处理相符，但不能仅凭两小时历史结果就认定实现规则；具体还须以老师平台前端校验和课程市场规则为准。

该阶段增加 `modeled_price_matching_hours`、`modeled_price_mismatch_periods`、`modeled_price_mismatch_points` 和两侧观测峰值字段，只标示诊断，不修改出清求解或报价曲线。
