# PMSS 真实历史机组出力固定下的 DC 潮流验证（阶段六）

## 最关键的发现：区分“机组出清偏差”和“网络模型偏差”

在老师平台已经获得授权、经过脱敏、仅用于历史研究的 **2025-09-01 39节点/46线路/10机组** 日前案例中，PowerBid 做了两套不同的 **24小时、共1,104个相同线路观测点** 的计算：

| 研究实验 | 输入的机组出力 | 使用网架 | 相比历史PMSS线路绝对潮流的MAE |
|---|---|---|---|
| A. 原始报价本地独立出清 | PowerBid DC-OPF 根据原始申报报价重新决定机组中标量 | 核实过的39节点、46线路 | **43.34329 MW** |
| B. 固定历史机组出力的 DC 潮流 | **直接用老师 PMSS 已出清的实际机组中标量**，不得改动或重新优化 | 同一份39节点、46线路 | **6.00763 MW** |

这两个误差使用的历史线路点完全一致、同一天、同一拓扑，因此可直接对比。幅值误差相差约37.34MW，条件潮流误差相当于独立出清潮流误差的13.86%。

同一日期的原报价 DC-OPF **机组中标量 MAE 约47.10MW**，节点 LMP MAE 约397.37（原 PMSS 电价单位和结算规则尚需核验）。

另一个窗口的真实 PMSS 电网 KCL 检查发现：所有机组总发电量与系统负荷几乎严格平衡（数值误差级别），**逐节点的实际潮流与注入 KCL 平均残差约8.53MW，最大节点约66.66MW**。这意味着对真实支路流向、交流潮流、是否存在其他注入/损耗、历史表的数据口径仍有必要核实。

**该对照支持“机组分配/市场出清规则不一致比单纯线路参数误差更值得优先排查”的工程判断，但绝不证明误差的37.34MW都由某一特定原因造成，也不代表任何新报价的PMSS收益变好了。**

## 新增模块

- \`src/powerbid/fixed_injection_diagnostics.py\`：严格读取原市场 DA 已出清的24小时机组出力；逐小时计算节点净注入 \`generation - nodal demand\`，在给定电抗和线路模型上用 **DC load flow** 直接求相角、线路潮流。没有优化机组出力，也没有调用 PMSS 出清。
- \`src/powerbid/flow_error_attribution.py\`：对照此前 \`historical_validation.validate_historical_day\` 的同一日、同一历史点的 *original-bid DC OPF* 误差和新模块的 *PMSS fixed-injection DC flow* 误差。严格检查是否使用同一组支路时段；只有24小时系统发电全部完整且平衡、观测覆盖相同，才输出二者的**直接误差差值**。
- \`app/pages/6_模型可靠性回测.py\`：此前的多日期回测页面增加“误差归因对照”区域、选定日期的两项误差、支路方向正反对比、线路误差排名及审阅JSON导出。
- \`tests/test_fixed_injection_diagnostics.py\` 和 \`tests/test_flow_error_attribution.py\`：验证两节点及三角网、流向翻转、观测缺失、负荷不平衡与超过额定容量时的处理。

## DC 潮流的物理计算

定义单位节点净注入：

\[
p_n=\sum_{g\in n}P^{PMSS,actual}_g-D_n.
\]

使用验证过的线路 \`reactancePu\` 和同一基准 \`baseMva\`，建立直流节点导纳矩阵 \`B\`：

\[
B_{ii} = \sum_{j:(i,j)\in E} \frac{S_{base}}{x_{ij}},\qquad
B_{ij} = -\sum_{\ell:i\leftrightarrow j}\frac{S_{base}}{x_\ell}.
\]

固定参考节点相角为0，求解 \`B_reduced * theta = p_non_slack\`，计算：

\[
f_\ell = \frac{S_{base}}{x_\ell}
(\theta_{\ell,from}-\theta_{\ell,to}).
\]

**不会调度新的发电量来“配平”、不会改变实际观测、不会把缺失值填成0、不会自动把线路潮流剪裁到上限，也不会调整电抗来拟合结果。**

- 机组历史中标数据缺失：该小时标记 \`MISSING_GENERATION\`，跳过；
- 总注入与负荷差大于显式 \`balance_tolerance_mw\`（默认0.1MW）：标记 \`GENERATION_LOAD_IMBALANCE\`，跳过；
- 历史线路观测缺失：仅跳过缺失的支路时段，不伪造0；
- 方向约定尚未证实：分别报告原方向、全局反向及绝对值 MAE；严禁暗改 PMSS 历史流向；
- 预测网络潮流超过额定限额：记录超额次数，不假装是已经满足线路约束的出清解。

**关于平衡容差：** 在0.1MW阈值内的极小总注入偏差由参考节点数值平衡项吸收，因此报告始终保留原始总注入差；不会产生显式额外机组或改写任何 PMSS 历史数据。这是潮流诊断，不是实际市场出清。

## 如何查看

在受控环境打开 Streamlit：

\`\`\`sh
pip install -e '.[ui,strategy]'
streamlit run app/streamlit_app.py
\`\`\`

进入 **模型可靠性回测** 页面，上传由原有 PMSS 只读白名单导出器导出的脱敏历史案例（必须带 \`dcNetwork\`、\`results\`、\`historicalBacktestOnly=true\`、\`caseDate\`）。

启动回测后，选择具体日期。在原机组、节点、线路误差表下新增“误差归因对照”，并按固定历史出力时的潮流误差排序列出最可疑的线路，方便针对性核查线路口径和 PMSS 电气参数。

导出的 JSON 只包含误差统计、用户阈值、日期、原模型误差及固定注入对照，不包含机组历史原始电量序列、原始报价、平台账号或凭证。

## 下一阶段技术优先级

1. **机组出清机理**：先核对 PMSS 实际机组启停、备用、成本/报价单位、最小出力、爬坡、系统侧约束；如果机组中标量差异显著，独立 DC-OPF 潮流误差高是合理的连锁表现。
2. **剩余潮流差异**：重点检查固定真实出力后仍偏离较大的线路、变压器等值电抗/变比、PMSS 历史潮流的方向/单位，以及 AC、网损和可能遗漏的注入/负荷。
3. **节点 LMP 异常小时**：与另一个窗口已定位的11、17时段电价例外联动，核实不同价格上限、不同结算/出清算法和可能的约束影子价格；绝不通过硬截断、删除异常小时来伪造低误差。
4. **多日期留出验证**：当前只有一日真实案例且它是事后固定注入；不能据此宣布未来报价推荐可靠，也不能以某一天的误差缩减值调参后宣称市场策略收益增加。
5. 在有明确授权的测试环境中、限制试验预算和保留原始案例的前提下再讨论 PMSS 真实重出清。当前这份代码**不会向老师 PMSS 发送任何保存或执行请求**。

所有真实案例文件只保留在受控服务器私有目录，绝不进入 Git。
