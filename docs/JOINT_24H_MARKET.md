# PowerBid：24小时机组启停 + DC 网络联合出清（V4）

## 当前成果和明确边界

PowerBid 的这一阶段不再将“单区价格搜索”、“机组自调度”、“逐小时 DC 节点出清”和“事后物理筛查”简单串联，而是新增 **24小时一体化混合整数市场模型（MILP）**：

- 所有机组每小时的启停状态、启动/停机决策及分段中标电量；
- 机组最小/最大出力、正常爬坡、启停过渡出力、最短连续开停机时间、初始状态；
- 所有节点逐小时功率平衡、DC 电抗潮流与线路有功输送限制；
- 与机组启停成本共同计算的全市场申报成本目标；
- 给定最优二元启停结果后，**固定这些整数状态重新运行线性规划**，计算用于研究的 DC 节点价格；
- 在上述联合约束下，比较多种发电商报价方案的模拟利润与下行情景收益。

**这仍不是老师 PMSS 的真实电力市场出清，也没有读写老师平台接口。** 只是实现了发电商报价研究使用的独立、可重算、带物理约束的本地网络市场代理模型。

## 一、目标与核心约束

每台机组 \(g\)，每小时 \(t=1,\dots,24\)，每段报价 \(k\)：

- \(q_{gtk}\)：中标电量，0 到该段申报上界；
- \(u_{gt}\)：开机状态（0/1）；
- \(v_{gt}\)：启动（0/1）；
- \(w_{gt}\)：停机（0/1）；
- \(f_{\ell t}\)：线路有功潮流；
- \(\theta_{nt}\)：节点相角（固定参考节点为 0）。

最小化**申报价格成本 + 假定启停成本**：

\[
\min \sum_{g,t,k}c^{bid}_{gtk}q_{gtk}
 +\sum_{g,t}\left(S_g^{start}v_{gt}+S_g^{stop}w_{gt}\right).
\]

以\(P_{gt}=\sum_kq_{gtk}\) 表示机组中标出力，联合施加：

\[
P_g^{min}u_{gt}\le P_{gt}\le P_g^{max}u_{gt},\qquad
u_{gt}-u_{g,t-1}=v_{gt}-w_{gt}.
\]

启动和正常爬坡分别约束：

\[
P_{gt}-P_{g,t-1}\le R_g^{up}u_{g,t-1}
  +R_g^{startup}v_{gt}.
\]

下降与停机也有对应约束。最短连续运行和停机用过去时段启动、停机二元变量的窗口不等式约束。第1小时使用明确输入的第0小时机组状态/出力/状态持续小时数。

对每个节点施加：

\[
\sum_{g\in n} P_{gt}-\sum_{\ell:n\to *}f_{\ell t}
 +\sum_{\ell:*\to n}f_{\ell t}=D_{nt}.
\]

对每条线路施加：

\[
f_{\ell t}=\frac{S_\mathrm{base}}{x_\ell}
  (\theta_{\mathrm{from},t}-\theta_{\mathrm{to},t}),\quad
-\bar F_\ell \le f_{\ell t}\le\bar F_\ell.
\]

这使每个小时的机组约束与电网约束在**同一个24小时 MILP** 内生效。若不存在可行解、求解器超时或未能证明最优，则直接报错，不虚构报价利润。

### 为什么价格需要二次求解？

MILP 里含开/停机整数状态，整数优化本身没有可直接当作标准 LMP 的普适影子价格。本实现：

1. 使用 SciPy / HiGHS 求整个24小时 MILP；
2. 固定所有开机、启动、停机二元变量为最优状态；
3. 在同一模型上重新求解连续线性规划；
4. 读取每个节点功率平衡的 LP 对偶值，作为**固定启停状态下的示意 DC 节点边际价格**。

这些价格不是老师 PMSS 的实际结算价格，也不覆盖机组启停成本的全部成本补偿（uplift）机制。

### 日末处理

- \`complete\`：禁止日末过晚开机/停机，以确保最短连续状态时间在当天结束。
- \`carryover\`：允许剩余开停机义务带到下一天。**后续跨日调用必须显式传递状态及其连续持续时间**；本阶段没有自动跨日迭代。

## 二、报价评价

\`powerbid.joint_strategy.compare_joint_bids\` 接收原始报价及候选策略，在**每个场景中重新运行24小时联合出清**，不能把某个历史节点电价固定不变。

目标机组离线净利润代理：

\[
\Pi_g^{proxy}=
\sum_{t=1}^{24}
\left[
  (\lambda^{DC,fixUC}_{n(g),t}-c_g^{assumed}) P_{gt}
  -S_g^{start}v_{gt}
  -S_g^{stop}w_{gt}
\right].
\]

按合成情景权重得到预期利润、最差情景利润、下行风险（CVaR-like）利润、风险加权评分。若某个情景无法完成联合出清，则停止并报告不可行，不会冒充没有亏损。

每轮最多6个策略、每个策略最多3个合成情景，避免无节制地消耗 MILP 求解时间。计算结果只表示所搜索策略集合内的相对优劣，不是理论全局最优，也不是 PMSS 真实收益。

## 三、输入与示例

新增 Streamlit 页面：

\`app/pages/5_24小时联合优化.py\`

必须完整上传三个文件：

1. 与原有代码兼容的脱敏 \`PMSSSnapshot\`（24小时申报和历史场景负荷）；
2. 已验证的 \`DcNetwork\`（节点、支路电抗/限额、机组—节点映射、逐节点24小时负荷、参考节点、基准容量和来源信息）；

## 四、与 PMSS 真实历史出清如何对接？

\`powerbid.joint_feedback.compare_joint_baseline_history\` 只允许对 **原始已申报曲线** 的**中性情景**做只读历史回测：

- 必须存在同日24时段、DA 市场真实结果；
- 所有机组、节点、支路 ID 与已核实模型严格一致；
- 记录缺失的时段保持缺失，不补0；
- 提供目标机组中标 MAE/RMSE、所有机组中标 MAE、节点 LMP MAE、线路潮流**绝对值** MAE；
- 不从旧历史数据中捏造新策略实际市场结算。

尤其是：老师 PMSS 的真实机组节点对应、电网电抗与热稳定限额尚未全部确认。不能因为合成模型测试通过就宣称“真实39节点网络已完成联合优化”。

## 五、现阶段尚缺

- 真实 PMSS 网络/机组映射的严格只读提取与多日期留出回测；
- AC 电压/无功/网损、N-1、备用、爬坡备用、复杂边际成本、热态启停成本；
- PMSS 出清算法实际处理的市场约束、定价、补偿及结算口径；
- PMSS 测试环境中 **单独授权、限次数、可回滚** 的报价试验闭环；
- 多策略参数搜索更复杂的外层优化，以及强化学习。

因此，当前系统拥有可独立工作的24小时联合网络报价**研究引擎**，但绝不以此取代老师 PMSS 平台。
