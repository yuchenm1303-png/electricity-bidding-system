# PowerBid 小组作业 MVP · 交付与演示流程

这一版的验收重点是 **完整、可重复演示的操作闭环**，不是追求在未知机组物理参数下精确复现 PMSS 出清。正式站点需先确认已经部署包含本功能的版本；GitHub 合并 **不等于** 生产部署。

## 演示路线（PC）

1. 打开正式首页 `/`，点击「进入工作台」，按账号系统配置完成登录。
2. 在「决策工作台」核对市场负荷、机组容量、申报价和边际成本。
3. 点击「运行报价分析」；系统真正调用后端 `POST /api/optimize`，计算候选报价、出清价、中标量与模拟利润。
4. 在「策略分析」查看推荐报价、收益曲线以及完整试算明细。点击「导出 CSV」获取候选明细；点击「下载完整报告」保存一个 **可离线打开、可由浏览器打印为 PDF** 的 HTML 报告，包含本轮输入、机组申报和结果。
5. 打开「参数」，把负荷等参数调节后选择「风险分析」；重新运行，在「压力情景」页面查看各情景、预计利润、风险结果并导出报告。报告中的输入固定为 **实际计算时的参数快照**；再次编辑尚未运行的控件不会篡改旧报告。
6. 在「PMSS 市场分析」导入 **经批准、无密钥或认证信息的只读脱敏快照**，先检查，再可运行本地五段报价搜索及 DC 网络对照。本页不得提交报价、运行真实出清或修改老师平台。
7. 用窄屏手机打开工作台，侧栏菜单应可打开、切换页面并自动收起，页面不出现整个文档横向溢出。

## 一键浏览器回归（独立候选，不接生产账号）

```bash
# 先构建候选镜像，再在仅绑定 127.0.0.1 的端口启动 QA
docker build -t powerbid-mvp-candidate:qa -f Dockerfile.studio .
docker run -d --rm --name powerbid-mvp-qa -p 127.0.0.1:18570:8000 \
  -e POWERBID_AUTH_ENABLED=0 powerbid-mvp-candidate:qa
python scripts/smoke_powerbid_mvp_browser.py --origin http://127.0.0.1:18570
docker stop powerbid-mvp-qa
```

仅 **隔离 QA 实例** 可以设为未启用登录；**生产绝不能复制这一配置**。脚本本身强制只允许 localhost，使用项目自带示例与真实本地优化后端，不读取任何老师私人数据，不使用平台账号。执行前需要在本机安装 Playwright Python 库和 Chrome，Chrome 默认路径为 `/usr/bin/google-chrome`。

## 交付判定

- **通过**：已登录的工作台可读取场景、更新参数、单场景/风险优化、展示报告；CSV 与独立 HTML 报告能下载并离线打开；手机菜单可以点选导航；浏览器运行无异常。
- **需要另行验证**：生产环境登录/注册/权限及第三方登录完整流程；正式站是否部署对应主分支与上述功能；移动设备真机表现。
- **后续研究，非本版交付阻断**：PMSS 实际出清完全复现、真实机组物理参数验证与全天 DC+UC 联合 MILP、通过独立留出期验证真实报价收益。
- **边界**：默认场景为教学仿真。即使网页出现“推荐报价”，也不代表在真实 PMSS 上提交、出清、结算或验证收益。

**报告使用**：下载 `powerbid_single_full_report.html` 或 `powerbid_risk_full_report.html` 后用 Chrome/Edge 打开，按 `Ctrl+P` 选择“另存为 PDF”。单独的 CSV 文件用于核对和后续作图。
