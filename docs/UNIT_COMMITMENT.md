# PowerBid：24h 机组物理约束优化与 PMSS 只读评价

这是在策略研究室 V2 之上新增的 **24 小时热机组启停优化** 研究模块。策略生成、运行计划、市场出清是三个不同问题，不能互相冒充。

## 1. 输入边界（必须核验）

仅凭 PMSS 机组树中的 \`runningCost\`、\`pdAdjustMin\`、\`pdAdjustMax\` 不足以证明机组实际运行可行。以下参数必须来自课程材料或由用户明确输入并核验：

- 稳定最小与最大出力 (MW)
- 持续运行爬坡、降坡上限 (MW/h)
- 启动小时与停机前一小时允许的出力上限 (MW)
- 最小连续开机、停机小时数
- 单次启动、停机成本（与预测利润相同货币单位）
- 计算第 1 小时之前的运行状态、实际出力及该状态连续持续小时数
- 24 个时段的**独立电价预测**及来源说明
- 真实边际成本（此阶段仍以常量 $/MWh 表示，课程字段单位必须核验）

程序不再暗自假定机组可以瞬间从 0 跳到最大功率。没有缺省爬坡、启动/停机上限等伪造值。

## 2. 优化模型

可用 scipy.optimize.milp (HiGHS) 求解混合整数线性问题。对时段 $t=1,\ldots,24$：

- $p_t$: 机组计划有功出力 (MW)
- $u_t$: 是否开机 (0/1)
- $v_t$: 是否启动 (0/1)
- $w_t$: 是否停机 (0/1)

目标：

\[
\max \sum_{t=1}^{24}
[(\widehat{\lambda}_t-c)p_t-C_{\rm start} v_t-C_{\rm stop}w_t]
\]

约束包括：

\[
P_{\min}u_t\le p_t\le P_{\max}u_t,\quad
u_t-u_{t-1}=v_t-w_t,
\]
\[
p_t-p_{t-1}\le R_\uparrow u_{t-1}+R_{\rm start}v_t,
\]
\[
p_{t-1}-p_t\le R_\downarrow u_t+R_{\rm stop}w_t.
\]

同时设置最短连续开/停机小时限制，并正确处理第 0 小时状态和此前已经持续的时间。

**日末处理模式：**

- \`complete\`：日内结束前满足最短开/停机时间，保守地禁止过晚启动/停机。
- \`carryover\`：允许次日继续满足义务，并输出还须持续多少小时。要求后续计划强制传递该状态。

注意：这还是**针对给定外生预测电价的机组自调度优化**，不是 PMSS 网络市场出清。预测电价本身不随本机组报价变化；尚未涉及最小发电承诺的市场规则、储能、备用、复杂成本曲线、机组热态启动、日前实时耦合。

## 3. 策略物理筛查

独立的 \`physical_strategy_audit.py\` 使用策略研究室已经产生的本地 *accepted_mw* 曲线，逐小时检查本机组是否违反：

- 正常最大/最小出力
- 正常运行爬坡/降坡
- 启停过渡功率上限
- 最短运行/停机时间和初始状态
- 日末状态持续义务

对各合成市场压力情景累计通过概率，并在全部情景均通过时才标记为 *physical-screened candidate*。若全部不通过，就**不推荐物理上可靠的候选**。单一目标机组通过这些检查，并不意味着 PMSS 网络约束或其他机组能满足出清。

当 \`Pmin=0\` 时，只通过是否发电来反推开机状态并不可靠；主优化器保留显式开停机变量，不会将零出力的物理审查冒充可靠事实。

## 4. 老师 PMSS 已出清结果（只读）

\`observed_feedback.py\` 读取**已经出清的** 24 时段机组出力、价格及平台收入。不执行 PMSS 出清、不保存报价、不开启后台循环。

- 机组 ID 和 DA/RT 市场类型必须精确对应，不跨机组混用。
- 缺失小时数保持为 None，不替换为 0，不用不完整序列做物理审查。
- 平台记录收入沿用原 API 数值尺度；不擅自当作“元”或与边际成本混算。
- 历史实际出清记录不能当作“本次新策略的出清结果”或未来预测。
- 当历史真实序列与填写的技术参数冲突，应先核对技术参数与初始状态，不武断判断 PMSS 错误。

## 5. 使用和测试

在现有基础上运行：

\`\`\`sh
pip install -e '.[ui,strategy]'
streamlit run app/streamlit_app.py
\`\`\`

进入“机组约束优化”页面，上传与策略研究室相同的**脱敏只读 PMSS 快照**，人工填写和确认参数、独立24小时预测电价。页面展示24小时启停/出力计划、收益、策略物理审查，必要时展示脱敏快照中的 PMSS 历史记录。导出的 JSON 为离线审核文件，不是可以直接提交的 PMSS 报价。

\`\`\`sh
python -m pytest tests/test_unit_commitment.py tests/test_physical_strategy_audit.py tests/test_observed_feedback.py -q
ruff check .
\`\`\`
